# منصة آل الزين للعلوم القانونية والعدلية

نسخة جديدة من المنصة تعمل على **Supabase (PostgreSQL)** بدلاً من SQLite، مع الحفاظ على الهوية القانونية العربية RTL والفصل الصارم بين البوابات الثلاث.

## الحالة الحالية

| الطبقة | الحالة |
| --- | --- |
| قاعدة البيانات (25 جدولاً + RLS + فهارس) | ✅ مبنية ومُتحقَّق منها |
| حاوية التخزين `platform-files` | ✅ خاصة وجاهزة |
| خادم Express + قوالب EJS + RTL | ✅ هيكل كامل |
| المصادقة (scrypt + جلسات مخصصة) | ✅ تعمل |
| البوابات الثلاث والفصل الصارم | ✅ تعمل ومُختبرة |
| لوحات المالك والأستاذ والطالب | ✅ بيانات حقيقية |
| المقررات، المحاضرات، الحضور، الاختبارات، الواجبات، النقاط، المنتدى، المكتبة، النشر، الأرشيف، التصدير | ✅ تعمل |
| إنشاء الحسابات والدفعات (يدوي + إكسل) والتسجيل في المقررات مع التوقيف لكل مقرر | ✅ تعمل ومُختبرة |

## التشغيل

```bash
npm install
npm run seed:test   # مرة واحدة: حسابات اختبار للبوابات
npm start           # http://localhost:3001
npm run dev         # مع إعادة التشغيل التلقائي
```

> المنفذ الافتراضي 3001 لأن المنفذ 3000 مشغول بخادم قديم من جلسة سابقة. غيّر `PORT` في `.env` عند الحاجة.

## مسارات الطلاب ونظام التقييم

التمييز مبني على **مسار الطالب** (حقل `track` في حساب الطالب) بصرف النظر عن مسار المقرر:

| المسار | أداة التقييم الظاهرة | مخطط الدرجة |
| --- | --- | --- |
| `bachelor` — مسار البكالوريوس | الاختبارات فقط (الواجبات مخفية) | حضور 30% + اختبارات 70% |
| `equiv` — قسم المعادلة | الواجبات فقط (الاختبارات مخفية) | حضور 30% + واجبات 70% |

- القوالب/النقاط: الحضور 30 نقطة هي نفسها في المسارين.
- أي مسار جديد يُضاف مستقبلاً: سطر واحد في `src/lib/tracks.js` (`TRACK_PROFILES`).
- التحكم عن بُعد: تغيير مسار الطالب من «تعديل بيانات الطالب» (متاح للمالك والأستاذ الكامل).
- الطالب التجريبي `2024003` حالياً على مسار `equiv` للعرض.

## قواعد البوابات (منطق الخادم)

| البوابة | يُسمح | يُرفض (403) |
| --- | --- | --- |
| `owner` | المالك (أقل `id` بدور `teacher`) | أي أستاذ أو طالب |
| `teacher` | الأساتذة، ويُستثنى المالك | المالك والطلاب |
| `student` | الطلاب | المالك والأساتذة |

- مفتاح `owner_all_gates` (افتراضي `0`): عند تفعيله يستطيع **المالك فقط** دخول البوابات الثلاث.
- أي محاولة مرفوضة تُسجَّل في `archived_records` باسم `login_denied` مع المعرّف والدور والبوابة و`IP` والوقت.
- الجلسة: رمز عشوائي 256-bit في كوكي `HttpOnly`، وتُخزَّن تجزئته (`sha256`) في جدول `sessions` فقط.
- تغيير كلمة المرور يُبطل كل الجلسات الأخرى للمستخدم.
- الدخول بالرمز الموحد فقط (`BM/BF/EQ/EX/PG/TE/AD` + تسلسل) — لا بريد دخول. كل الحسابات تُنشأ من الإدارة فقط، وكل جلسة أولى تلزم بتغيير كلمة المرور وإدخال البريد قبل أي صفحة.
- يُقفل الحساب 15 دقيقة تلقائياً بعد 5 محاولات فاشلة متتالية (إضافة إلى حد المعدل لكل IP)، ويُسجَّل إعادة توليد كلمة المرور في `archived_records` باسم `password_reset`.

## التسجيل المركزي والتسجيل في المقررات

كل الحسابات تُنشأ من الإدارة فقط، وتكون **نشطة وجاهزة للدخول فوراً** بلا حالة انتظار:

- **المالك فقط** ينشئ المستخدمين (فردياً، بدفعة نصوص، أو بدفعة إكسل) ويعيد تعيين كلمات المرور ويوقف الحساب عاماً.
- **الأستاذ لا ينشئ حسابات**؛ دوره يقتصر على تسجيل الطلاب الحاليين في **مقرراته هو فقط** (أي محاولة على مقرر لا يملكه تُرفض 403).
- بيانات الدخول تُعرض مرة واحدة عند الإنشاء (رمز + كلمة مرور) للنسخ والطباعة، ولا تُخزَّن كلمة المرور صريحة أبداً.
- لا يُعتمد البريد للدخول أبداً؛ يُدخله المستخدم إلزامياً مع تغيير كلمة المرور في أول جلسة.

### دفعات إكسل

من «المستخدمون» ← «تسجيل دفعة إكسل» (أو «لصق دفعة»):

- الأعمدة المقروءة: **1) الاسم الرباعي (إلزامي) 2) المسار/النوع (اختياري) 3) المستوى 1–4 (اختياري)**. يُتجاهل صف العنوان إن وُجد، ولا تُقرأ الأعمدة الأخرى.
- الصيغ المدعومة: `xlsx` / `xlsm` / `csv` — حتى **2 ميجابايت** و**300 اسم** كحد أقصى.
- **المسار الافتراضي والمستوى** يُختاران في النموذج ويُطبَّقان على الصفوف التي تترك العمودين 2 و3 فارغين (بما فيها ملفات عمود الأسماء القديمة). إن وُجد عمود المسار، يُحلَّ كل صف إلى مساره (`bachelor_m`/`BM`/`طلاب`/`ذكر`، `bachelor_f`/`BF`/`طالبات`/`أنثى`، `equiv`/`EQ`، `external`/`EX`، `grad`/`PG`) ويُعطى **الرمز التسلسلي التالي لبادئته**، فيمكن خلط الطلاب والطالبات والمسارات في ملف واحد. القيمة غير المعروفة أو المستوى غير الصالح يُبلَّغ عن سطرها ولا يُنشأ حسابها.
- `resolveTrackAlias()` في `src/lib/tracks.js` هو محلّ الأسماء البديلة، و`provisionUser()` يتولّى التسلسل المستقل لكل بادئة.
- النتيجة تعرض الرموز وكلمات المرور للنسخ والطباعة، وتُسجَّل عملية الاستيراد في `archived_records` باسم `bulk_import`.
- تُقرأ الملفات في الذاكرة ولا تُحفظ على الخادم بعد المعالجة.

### التسجيل في المقرر والتوقيف لكل مقرر

من صفحة المقرر ← «إضافة طلاب»:

- تصفية اختيارية بالمسار والمستوى (افتراضياً حسب مسار/مستوى المقرر) مع رابط «عرض كل المسارات والمستويات»، وبحث بالاسم/الرمز. **الاختيار حر** ولا يُقيّد بمسار أو مستوى الطالب.
- يمكن تحديد عدة طلاب وتسجيلهم في **عدة مقررات دفعة واحدة**؛ المكرر يُتخطى تلقائياً، ويصل الطالب إشعاراً داخلياً فور التسجيل.
- **طالب فاته الكشف؟** يستطيع **المالك وحده** فتح «فاته الكشف؟ أنشئ حسابه وسجّله هنا مباشرة» داخل نفس الشاشة: يُنشأ الحساب برمز تالٍ وكلمة مرور تُعرض مرة واحدة، ويُسجَّل فوراً في المقرر الحالي مع إشعار داخلي وسجل تدقيق `quick_enroll`. الأستاذ لا يرى هذا النموذج ولا يمكنه الوصول إليه (403)، التزاماً بقاعدة «الأستاذ لا ينشئ حسابات».
- في صفحة المقرر تظهر حالتان منفصلتان: **حالة الحساب** (عامة، من صلاحية المالك) و**التسجيل في هذا المقرر** (خاصة بالمقرر، من صلاحية المالك أو الأستاذ المسؤول).
- «توقيف في المقرر» يوقف وصول الطالب إلى **هذا المقرر فقط** في قائمة المقررات والوصول المباشر والمنتدى والإشعارات، دون لمس حسابه؛ باقي مقرراته تعمل طبيعياً. «إعادة تنشيط» تُرجعه فوراً.
- التوقيف والإعادة يُرسلان إشعاراً داخلياً للطالب ويُسجَّلان في `archived_records` باسم `enrollment_status`.

> التوقيف الخاص بالمقرر مخزَّن في `enrollments.status` (`active` / `suspended`) ولا يغيّر `users.is_active` أبداً.

## حسابات الاختبار

| الدور | الرمز الموحد | كلمة المرور |
| --- | --- | --- |
| المالك | `AD0001` | `HLDCCYJJDZT3` |
| أستاذ | `TE0001` | `Teacher1234` |
| طالب | `BM0001` | `Student1234` |

الرموز تُولّد آلياً عند الإنشاء حسب المسار: `BM` (طلاب) · `BF` (طالبات) · `EQ` (المعادلة) · `EX` (من الخارج) · `PG` (الدراسات العليا) · `TE` (أستاذ) · `AD` (المالك). البريد ليس وسيلة دخول — يُدخله المستخدم إلزامياً عند أول جلسة مع تغيير كلمة المرور. الطالبات يحملن `BF0001`–`BF0004` وطالب المعادلة `EQ0001` (البيانات التجريبية كما أُنشئت دون كلمات مرور معروفة).

> بيانات اختبار مؤقتة — تُحذف قبل الإطلاق الفعلي.

## ملاحظة توافق كلمات المرور

يدعم التحقق صيغتين من تجزئة scrypt:

- `scrypt$N$r$p$saltHex$hashHex` — الصيغة التي يكتبها التطبيق.
- `s1$N$r$p$saltB64$hashB64` — صيغة البيانات التجريبية السابقة (`scripts/seed-users.mjs`).

## ترحيلات قاعدة البيانات

تُطبَّق بالترتيب عبر `node scripts/run-sql.mjs supabase/migrations/<الملف>.sql`. أحدثها `0011_enrollment_status.sql` الذي يضيف `enrollments.status` لدعم التوقيف لكل مقرر.

## الخطوات التالية المقترحة

1. تصدير قوائم الطلاب/الدرجات إلى Excel/Word وتحسين طباعة بيانات الدفعات.
2. تقارير إحصائية أعمق للحضور والأداء حسب المسار والمستوى.
3. إشعارات بريدية/رسائل خارجية بجانب الإشعارات الداخلية.
4. نهاية واجهة إدارة المكتبة والعلامة المائية على PDF.

## العمل مع الفريق (Git / GitHub)

1. استنساخ المستودع: `git clone <رابط-المستودع>` ثم الدخول إلى المجلد.
2. إنشاء البيئة المحلية: انسخ `.env.example` إلى `.env` واملأ المفاتيح من لوحة Supabase. **لا ترفع `.env` ولا أي ملف أسرار إلى Git.**
3. تثبيت الحزم: `npm install`.
4. لكل مهمة فرع مستقل: `git switch -c feature/اسم-المهمة`.
5. الالتزام: `git add .` ثم `git commit -m "وصف مختصر"`.
6. النشر وفتح طلب دمج (Pull Request): `git push -u origin feature/اسم-المهمة`.
7. لا تدفع إلى `main` مباشرة؛ بعد الدمج حدّث نسختك: `git switch main` ثم `git pull`.

> ملف `كلمة مرور سوبابيس.txt` مستبعد من Git عمداً. كل عضو يحصل على المفاتيح من المالك ويضعها في `.env` المحلي فقط.
