# Plan: العام الدراسي والفصلان — V1

## قرار المالك (2026-11-26): تصنيف العام مقابل الترقية

- **التصنيف الزمني يشمل كل المسارات:** الـbackfill في `0115` صنّف كل تسجيلات اليوم في «العام الحالي / الفصل الأول» بغض النظر عن المسار (`bachelor_m`، `bachelor_f`، `bachelor`، `equiv`، `external`، `grad`). هذا تعميم مقصود للبعد الزمني، وليس تغييراً في قواعد المسارات.
- **الترقية إلى عام جديد مقصورة على البكالوريوس فقط:** في `0116` تُدرَج تسجيلات `bachelor_m`/`bachelor_f` في العام التالي بعد إغلاق العام الحالي؛ المسارات الأخرى تُوقَف أو تُؤرشف بقرار المالك (`held` / `archived`) ولا تُرقَّى تلقائياً.
- لا يغيّر هذا القرار مهام التخطيط أدناه ولا نطاقها؛ هو توثيق للفرق بين تعميم التصنيف وتضييق الترقية.

## Task 1 — academic-schema (مكتمل)

- إضافة `academic_years` و`semesters` و`academic_policies` و`course_semester_results` و`graduation_approvals`.
- إضافة `users.academic_status` و`enrollments.year_id` و`enrollments.semester_id`.
- backfill: تسجيلات اليوم تصبح «العام الحالي / الفصل الأول».
- استبدال مفتاح `enrollments` المركّب، وإعادة تعريف الدوال الست التي كانت تستخدم `on conflict (course_id, student_id)`.
- rollback كامل + اختبار عقد.

Acceptance: الترحيل قابل للتطبيق كمعاملة واحدة، وال rollback يعيد المفتاح والتوقيعات السابقة.
Verify: `node --test tests` + فحص عن بعد قراءةً فقط.

## Task 2 — period-rules (مكتمل)

- `academic_preview_close_year`: عدد المسجلين، مرشحون للتخرج، حالات تحتاج قرار، عوائق.
- `academic_close_year_and_open_next`: إغلاق → إنشاء عام → تسجيلات جديدة → أرشفة → تدقيق في معاملة واحدة.
- منع الإغلاق مع أي قرار معلّق، ومنع فتح عام جديد قبل الإغلاق.
- النتيجة: `0116` وrollback واختبارات عقد مطبّقة؛ المعاينة الحية تمنع الإغلاق قبل تسجيل النتائج.

## Task 3 — result-decisions (مكتمل)

- حساب نقاط كل مقرر في كل فصل من `points_ledger`.
- حالة `pass / needs_decision / fail` مع توصية الأستاذ للقراءة فقط.
- قرار المالك مع سبب، وتجاوز رفض الأستاذ.
- فتح الفصل الثاني ونجاح العام بناءً على نتائج المقررات.
- النتيجة: `0117` وrollback واختبارات عقد مطبّقة؛ لم يُشغّل rebuild لأن سجل النقاط فارغ.
- تصحيح لاحق: `0118` أغلق الفصل الثاني الخالي للعام الحالي حتى يعمل شرط فتح الفصل الثاني.

## Task 4 — owner-ui (مكتمل)

- اختيار الفصل عند تسجيل طالب جديد، مقصور على `bachelor_m` و`bachelor_f` والفصول المفتوحة.
- شاشة إغلاق العام مع المعاينة والموافقة والأرشفة.
- قراءة نتائج المقررات ومرشحي التخرج عبر دوال مالك فقط، وقرارات مالك سببية، وتغيير حالة أكاديمية دون حذف.
- النتيجة: `0119` وrollback واختبارات عقد مطبّقة؛ ١٤٥ اختباراً (١٤١ ناجح، ٤ تخطي) وبناء ناجح.

## Task 5 — teacher-ui (مكتمل محلياً)

- صفحة `pages/teacher/results.html` تعرض نتائج مقررات الأستاذ المسندة في العام المفتوح، مع تصفية الفصل محلياً.
- زر واحد فقط للصفوف القابلة للتوصية: `teacher_record_result_recommendation` بقيمة `pass` أو `fail`، بلا أي تعديل للدرجات أو النقاط أو قرار المالك.
- الترحيل `0120_teacher_result_read.sql` مُطبَّق على Supabase داخل معاملة واحدة، مع rollback في `supabase/rollback/0120_teacher_result_read_rollback.sql`. الدالة `stable` و`security definer` و`search_path=public`، ومنحت لـ`authenticated` و`service_role` فقط؛ استدعاؤها بلا جلسة يعيد `{ok:false,error:'not allowed'}`.
- النتيجة: ١٥٥ اختباراً (١٥١ ناجح، ٤ تخطي) وبناء ناجح. لا نشر Pages ولا تغيير بيانات.

## Task 6 — verification (مكتمل)

- صلاحيات: كل جداول `public` مفعّل عليها RLS؛ لا منح كتابة مباشرة لـ`anon` أو `authenticated` على الجداول الحساسة؛ لا `EXECUTE` لـ`anon` على دوال `academic_` أو `teacher_` أو `management_` أو `owner_`.
- الدوال الحارسة: ١٦ دالة ذات صلة كلها `security definer` مع `search_path=public`، ومراجع الجداول في `0115`–`0120` موسومة بـ`public.`؛ `course_semester_results` و`graduation_approvals` و`audit_logs` بلا سياسات مباشرة ومحجوبة عن `anon`/`authenticated`، والوصول إليها عبر دوال المالك فقط.
- التخزين: حزمتان خاصتان `library` و`platform-files`، وأربع سياسات على `storage.objects` لـ`authenticated`. دوال الحافة: `ai-chat` و`owner-user-admin` بـ`verify_jwt=true`، و`legacy-login` بـ`false` لتدفق الرمز.
- البيانات الحقيقية قراءةً فقط: ٣٢٣ مستخدماً (٣١٧ طالباً، ٤ أساتذة، ٢ مساعد) و٧ حسابات Auth؛ المسارات `bachelor_f=220` و`bachelor_m=93` و`equiv=2` و`external=1` و`grad=1`؛ ٣٩٢ تسجيلاً، ٣٩١ نشطاً، ٣٩٢ في الفصل الأول وصفر في الثاني؛ العام `CURRENT` مفتوح والفصلان `open` ثم `closed`. السياسات ٣٠٠/١٥٠ ومصادر النقاط كما هي؛ النتائج والموافقات وسجل النقاط فارغة.
- النشر: بعد إذن صريح، نُفّذ `npm run build` ثم `npm run deploy:pages` من `web/`؛ فرع `gh-pages` يحمل ١١٣ ملفاً، والصفحتان `pages/owner/academic.html` و`pages/teacher/results.html` تعيدان ٢٠٠ مع كل أصولهما. لا تغيير بيانات ولا دفع إلى `main`. الاختبارات ١٥٥ (١٥١ ناجح، ٤ تخطي) والبناء ناجح.

Build order: 1 → 2 → 3 → 4 و5 → 6.

Verification checkpoints: بعد كل مهمة، `node --test tests` و`npm run build`، ولا نشر قبل إذن صريح. منح الإذن ونُشر في 2026-11-26، وتحقّق من رجوع الصفحات والأصول بـ٢٠٠.

## ملحق — تثبيت الدخول قبل التجارب العملية (2026-11-26)

- عادت رسالة «قاعدة البيانات غير مهيأ / أزرار المعاينة فقط» في الحزمة المنشورة. السبب الأول: إعداد Vite العام لم يكن متتبعاً، فبُنيت الحزمة بلا `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`. السبب الثاني: `legacy-login` استخدم `Buffer` دون استيراد في Deno، فأعاد HTTP 500 لرموز مثل `BF0001`، وظهر ذلك في سجلات Supabase.
- الإصلاح الجذري: `web/.env` عام متتبع بمفتاحين فقط؛ `buildConfig` يفشل البناء عند غياب الإعداد أو وجود value وهمي أو `sb_secret_`؛ `verify:deploy` يفحص الحزمة؛ `deploy:pages` يمنع النشر قبل نجاحهما؛ `legacy-login` يستورد `Buffer` ويحوّل أخطاء scrypt إلى رفض منظم.
- لا تغيير في بيانات Supabase أو الترحيلات `0115`–`0120`؛ تغيّر فقط نشر Pages وإعادة نشر دالة الحافة. `verify:login` يبقى فحصاً دائماً بلا كلمات مرور حقيقية.
