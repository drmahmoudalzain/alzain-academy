# دمج مميزات الواجهات القديمة — وثيقة التصميم

## الهدف

تحسين الصفحة العامة الحالية، ثم مراجعة التصاميم والواجهات القديمة ودمج التحسينات التي تخدم الواجهات المنشورة حديثاً، مع الإبقاء على مصادر البيانات الحقيقية، وسلوك الحفظ، وحدود الصلاحيات الحالية.

## الوضع الحالي والمصادر

- الصفحة الرئيسية في `web/index.html` حالياً مدخل مختصر إلى تسجيل الدخول؛ التصميم الأقدم الكامل موجود في `design/home.html`، وله نسخة منشورة تاريخياً في فرع `gh-pages`.
- الواجهات القديمة في `design/` ونسخة اللقطة `preview/old-ui/` تتضمن تصميمات دخول، ولوحة الطالب، وقائمة المحاضرات، وتفاصيل المحاضرة، والاختبار.
- تطبيق الويب الحالي متعدد الصفحات، ويستخدم Supabase RPC وRLS للبيانات والصلاحيات. واجهات الأستاذ الحالية متصلة ببياناته ومقيدة بصلاحياته.
- بعض التفاعلات والبيانات في الملفات القديمة تجريبية أو ثابتة. ليست مصدراً موثوقاً للبيانات أو منطق العمل.
- توجد تغييرات محلية سابقة في لوحة المالك وملفاتها؛ يجب الحفاظ عليها، وفحص أثرها قبل أي نشر يشملها.

## النطاق

1. **الرئيسية العامة:** استبدال المدخل المختصر بصفحة تعريف أكاديمية حديثة مستندة إلى `design/home.html`. الحفاظ على روابط صحيحة للمكتبة والدليل والبوابات، واستخدام الإحصاءات الديناميكية فقط إذا كان endpoint الحالي يدعمها. تحسين التحميل، تقليل الحركة المكلفة، واحترام `prefers-reduced-motion`.
2. **بوابة الطالب:** مطابقة التصميم القديم مع لوحة التحكم، وقائمة المحاضرات، وتفاصيل المحاضرة، والاختبارات والنتائج الحالية. نقل تحسينات العرض والتنقل والوضوح فقط حيث لا تكرر وظيفة حالية ولا تضعف الحفظ التلقائي أو توقيت الاختبار أو تسجيل الحضور.
3. **بوابة الأستاذ:** مراجعة ملفات التصميم القديمة مقابل اللوحات والصفحات الحالية. نقل تحسينات العرض المفيدة دون إضافة صلاحيات أو عمليات كتابة جديدة. إنشاء الواجبات فقط يبقى الإجراء الكتابي المسموح للأستاذ، وفق قاعدة البيانات.
4. **المالك والمساعد:** مقارنة ما يوجد فعلاً في الأرشيف القديم مع الصفحات الحالية. لا تُخترع بوابات أو وظائف قديمة غير موجودة؛ أي صفحة ما تزال قيد التطوير تبقى صريحة بشأن ذلك. الحفاظ على تعديلات المالك المحلية ومراجعتها مستقلاً.
5. **تسجيل الدخول:** تبقى صفحة الدخول الموحدة الحالية وأزرار المعاينة وزر كشف كلمة المرور. لا تُعاد صفحات دخول قديمة منفصلة ولا تُضمَّن بيانات دخول حقيقية أو كلمات مرور في الواجهة.

## خارج النطاق

- نقل بيانات أو أسئلة أو أرقام تجريبية من التصاميم القديمة.
- إضافة صلاحيات أو endpoints أو تغييرات قاعدة بيانات.
- نقل واجهة Express/EJS إلى تطبيق الويب الثابت أو تغيير بنية النشر.
- نشر أي ملفات أو تغييرات محلية غير مرتبطة قبل مراجعتها.

## البدائل

1. **نسخ صفحات التصميم القديمة مباشرة:** سريع بصرياً، لكنه يعيد بيانات ثابتة وروابط/تفاعلات قديمة ولا يتكامل تلقائياً مع RPC وRLS. مرفوض.
2. **دمج انتقائي ضمن التطبيق الحالي (المعتمد):** استخدام القديم كمرجع بصري وتجريبي، ونقل كل ميزة مفيدة إلى مكونات ومسارات التطبيق الحالي مع إبقاء البيانات والتفويض والحفظ الحالي. يوازن بين الاستفادة من القديم وسلامة التشغيل.
3. **توحيد CSS فقط:** أقل مخاطرة وأسرع، لكنه لا ينقل تحسينات التفاعل والتنقل التي طلبها المستخدم.

## قرارات التصميم

- الصفحة العامة: واجهة عربية RTL منسجمة مع ألوان الأكاديمية، خفيفة ومتجاوبة، بعناصر واضحة وروابط تعمل. لا اعتماد على عدادات أو إنجازات ثابتة، ولا رسوم ثقيلة أو حركات مستمرة.
- بقية الواجهات: لا إعادة كتابة كاملة على أساس أن كل ملف قديم ميزة مستقلة؛ تُعتمد مقارنة موثقة لكل ميزة: قديمة، حالية، قرار (إبقاء/نقل/استبعاد) وسبب.
- لا يُنقل أي عنصر بصري يغيّر معنى الصلاحية أو يوحي بإجراء غير متاح.
- يحافظ وضع المعاينة الحالي على كونه عرضاً فقط؛ لا يقرأ أو يكتب بيانات حقيقية من دون جلسة مصادق عليها.
- لا نشر إلا بعد نجاح البناء، وفحص المسارات والأدوار، ومراجعة التغييرات المحلية التي سيدخلها `dist`.

## معايير القبول

- الصفحة الرئيسية تعرّف بالأكاديمية وتوصل المستخدم إلى تسجيل الدخول والأقسام العامة دون روابط معطوبة، وتعمل عند 320/390/768/1024/1440 بكسل.
- كل واجهة قديمة محددة في `design/` أو `preview/old-ui/` لها مقابِل أو قرار استبعاد موثق؛ لا تُسقط وظيفة قديمة مفيدة بصمت.
- الاختبارات والمحاضرات تحتفظ بالحفظ الفعلي، والتحقق من الوقت، والتحضير عبر الخادم، ولا تعرض إجابات صحيحة أو بيانات نموذجية.
- صلاحيات المالك/الأستاذ/المساعد/الطالب تبقى مطابقة لـ RLS وRPC، ولا تنشأ كتابة جديدة للأستاذ.
- `npm run build` ينجح، والاختبار اليدوي يغطي الروابط الرئيسية، وأزرار المعاينة، وتخطيط الهاتف، والبوابات المتأثرة.
- ينجح النشر المصرح به على GitHub Pages، بعد التأكد من محتويات البناء وعدم تسريب `.env` أو بيانات اعتماد.
